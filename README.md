# skill-swipe


*Проект «Система автоматизированного подбора эксперта на стартап-проекты». Статус: черновик v1 для обсуждения с командой. Автор: аналитик.*


## 1. Обоснование выбора проекта

### 1.1. Проблема

- Основатели стартапов на ранней стадии не могут быстро найти экспертов (разработчиков, аналитиков, дизайнеров, ML-инженеров), готовых вписаться в проект по навыкам, времени и условиям.
- Эксперты не видят, какие проекты им подходят: информация разбросана по чатам, соцсетям и биржам.
- Существующие подходы (общие соцсети для профессионалов, биржи фриланса, чаты сообществ) требуют долгого ручного поиска и длинных форм. Отклик односторонний: одна сторона ищет, другая ждёт.

### 1.2. Предлагаемое решение

Telegram-бот с мини-приложением (Mini App) и механикой свайпов. Эксперт и владелец проекта видят ленту карточек, свайпают вправо при интересе. При взаимном интересе возникает мэтч и открывается чат. Навыки автоматически извлекаются из профилей, описаний проектов и резюме (ML-1). Лента ранжируется двусторонним матчингом с учётом истории свайпов (ML-2). Модели не обучаются: используются LLM и эмбеддинги через OpenRouter, история свайпов влияет на ранг через веса и повторное ранжирование.


### 1.3. Основные риски выбора

- Холодный старт: без истории свайпов ранжирование не обучить. Решение: стартуем с правилами на пересечении навыков, затем подключаем LLM и эмбеддинги через OpenRouter без обучения; синтетические данные для демо.
- Отсутствие реальных пользователей: нужны тестовые профили и 3-5 интервью.
- Один full stack разработчик закрывает весь frontend и часть backend: риск перегрузки.
- Персональные данные в резюме уходят во внешний LLM-сервис: нужны согласие, маскирование контактов и ограничение доступа.
