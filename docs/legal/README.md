# Юридические документы и тексты бота SkillSwipe

Папка содержит документы, которые пользователь видит или подтверждает (согласие, политика), и тексты сообщений бота. Состав данных, цели и сроки хранения берутся из реестра `docs/personal-data.md`, раздел 3. Задача: SSK-17.

> Тексты не являются юридической консультацией. Заключение юриста смоделировано (`docs/personal-data.md`, раздел 4.5). До публичного запуска документы нужно проверить юристу, подставить реквизиты оператора и заменить плейсхолдеры.

## Принцип: описываем только реализованное

Согласие и политика должны описывать то, что система делает сейчас. Если резюме не хранится, шифрования нет, ленты и чата нет, об этом нельзя писать как о существующем. Когда функция появляется (лента, чат, загрузка резюме в ИИ), выпускается новая версия документа и запрашивается повторное согласие.

## Состав папки

| Файл | Что это | Статус |
| --- | --- | --- |
| `README.md` | Правила оформления, версий и сверки | Готов |
| `bot-messages.ru.yaml` | Сообщения бота для онбординга (только ru) | Черновик, готов к переносу в `locales/ru.yaml` |
| `consent-core.ru.md` | Согласие `core` | Черновик готов (версия 1.0), ждёт плейсхолдеров и юридической проверки |
| `privacy-policy.ru.md` | Политика конфиденциальности | Черновик готов (версия 1.0), ждёт плейсхолдеров и юридической проверки |

**Отложено** (раздел 3.8 `docs/personal-data.md`, «Долг до публичного запуска»): согласия `profile_publication` (ст. 10.1), `digest`, `username_visibility`, `llm_processing` (если ML-1 войдёт в MVP, готовится отдельно), английские версии, тексты ботов чата и жалоб, хэш документов, GitHub Pages или домен оператора.

## Формат документа

Каждый документ в Markdown начинается с front matter:

```yaml
---
id: consent-core
title: Согласие на обработку персональных данных
version: "1.0"
date: 2026-11-25
lang: ru
---
```

| Поле | Значение |
| --- | --- |
| `id` | Идентификатор: `consent-core`, `privacy-policy` и т. п. Совпадает с началом имени файла |
| `title` | Заголовок документа |
| `version` | Версия в формате `мажор.минор` в кавычках (чтобы YAML не превратил её в число) |
| `date` | Дата вступления версии в силу, ГГГГ-ММ-ДД |
| `lang` | Язык, сейчас `ru`. Русская версия юридически значима |

Backend записывает в `consents.document_version` значение `version` документа, который видел пользователь.

## Правила версий

- **Смысловое изменение** (новые данные, цели, получатели, сроки, порядок отзыва): меняется мажор (`1.0` → `2.0`), требуется повторное согласие.
- **Редакционное изменение** (опечатка, уточнение формулировки без изменения смысла): меняется минор (`1.0` → `1.1`), повторное согласие не нужно.
- Версию меняет автор правки в том же PR, что и текст. Прошлые версии остаются в истории git.

## Плейсхолдеры

Реквизиты оператора и адреса пока не определены (решение D2), поэтому в документах стоят плейсхолдеры. Перед публичным запуском их нужно заменить.

| В документах | В словаре бота (подставляет backend из конфигурации) | Что это |
| --- | --- | --- |
| `[оператор]` | `{operator_name}` | Наименование или ФИО оператора |
| `[email]` | `{operator_email}` | Контакт для обращений и отзыва согласия |
| `[адрес]` | не используется | Адрес оператора (если потребуется юристу) |
| `[хостинг-провайдер]` | `{hosting_provider}` | Название хостинг-провайдера (D3, предварительно Yandex Cloud) |
| не используется | `{doc_version}` | Версия согласия, подставляется из front matter |
| не используется | `{mode_name}` | Название выбранного режима |

Ссылки на документы не вставляются в текст сообщений: они задаются как адреса кнопок в конфигурации (`consent_url`, `policy_url`).

## Где публикуются документы

В MVP (закрытое тестирование) ссылкой служит адрес файла в репозитории:

```
https://github.com/skill-swipe-team/skill-swipe/blob/main/docs/legal/<файл>
```

Для публичного запуска нужна отдельная страница на домене оператора (вопрос юристу: достаточно ли публикации без сайта оператора, ст. 18.1 152-ФЗ). Политику нужно указать в BotFather для бота свайпов.

## Формат сообщений бота

- Файл: `bot-messages.ru.yaml`, плоские ключи вида `onboarding.start.welcome`, плейсхолдеры в фигурных скобках (`str.format`).
- Разметка Telegram: HTML-подмножество (`<b>`, `<i>`, `<a>`), `parse_mode=HTML`. Символы `<`, `>` и `&` в обычном тексте нужно экранировать.
- Лимит сообщения Telegram 4096 символов.
- Backend переносит файл в `locales/ru.yaml` (вопрос B19), ключи не меняет без согласования с аналитиком: от них зависят тесты.

## Чек-лист сверки перед PR

Перед слиянием любого PR, меняющего документы или тексты бота, проверить совпадение:

| Что сверяем | Согласие | Политика | Тексты бота | Реестр (`personal-data.md`, раздел 3) |
| --- | --- | --- | --- | --- |
| Перечень данных | ☐ | ☐ | ☐ | ☐ |
| Цели обработки | ☐ | ☐ | ☐ | ☐ |
| Получатели (хостинг, при ИИ ещё провайдер LLM) | ☐ | ☐ | ☐ | ☐ |
| Сроки хранения и удаление | ☐ | ☐ | ☐ | ☐ |
| Порядок отзыва согласия и удаления аккаунта | ☐ | ☐ | ☐ | ☐ |
| Возраст 18+ | ☐ | ☐ | ☐ | ☐ |
| Версия и дата документа | ☐ | ☐ | ☐ | не применимо |
| Нет упоминаний нереализованных функций | ☐ | ☐ | ☐ | ☐ |
